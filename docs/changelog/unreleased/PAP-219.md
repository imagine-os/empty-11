### Security — PAP-219: threat model, hardening baseline and incident playbook

- STRIDE threat model across ten trust boundaries (browser, Tauri shell, API, Postgres/RLS, the
  Electric sync read path, jobs, realtime, agents and orchestrator, forges, third parties), with no
  empty cells: every row names a threat, a control id and how it is verified, or the issue that owns
  the gap.
- Hardening baseline as data: CSP with per-response nonces and three documented relaxations, CSRF
  origin checks, cookie and client-storage rules, CORS, rate limits, twenty secret classes with
  rotation runbooks and proof-of-death commands, and the dependency policy. Incident playbook with
  severities S0-S3, the paging path, containment per boundary, the 72-hour checklist and the
  post-mortem template.
- 103 controls (`SEC-<AREA>-<nn>`), 87 machine-verifiable, plus the agent deny list (23 rules, every
  S0 naming a backstop) with the build-loop push-to-main exception marked and dated.
- Paths: `docs/security/threat-model.md`, `docs/security/hardening-baseline.md`,
  `docs/security/incident-playbook.md`, `ops/security/controls.yaml`, `ops/security/agent-deny.yaml`,
  `ops/security/headers.json`, `scripts/security-controls.ts`.

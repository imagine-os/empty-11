### Added — PAP-433: module manifest schema, validator, CLI and golden fixtures

- `ModuleManifest` as a Zod 4 schema with `defineModule()` (literal-type inference for the kernel's
  typed tokens and `ModuleSettings<typeof module>`) and a pure, synchronous
  `validateManifest(manifest, { others, contracts })` returning ten stable diagnostic codes
  (`REQUIRES_UNRESOLVED`, `REQUIRES_RANGE_MISMATCH`, `DEPENDS_ON_DISAGREES`, `SLOT_UNKNOWN`,
  `TOPIC_UNDECLARED`, `OWNER_UNKNOWN`, `CYCLE`, `DUPLICATE_PROVIDER`, `PROVIDES_VERSION_MISMATCH`,
  `SCHEMA_INVALID`). Round-4 fields `secrets`, `lifecycle`, `resilience` and `issues` are reserved
  and validated; unknown fields still fail.
- Generated JSON Schema `manifest.schema.json` (`$id https://paperos.dev/schema/module-manifest/1`)
  from `pnpm --filter @paperos/core gen:schemas`, committed, drift-checked and ajv cross-checked
  against Zod; `pnpm --filter @paperos/core modules:validate` prints a table over every
  `module.manifest.json` in the workspace and exits non-zero on any error.
- Eighteen golden manifests (the seventeen modules of `docs/module-system.md` table 1.1 plus the
  kernel) and one deliberately broken fixture per diagnostic code; 158 tests including fast-check
  cycle properties and `expectTypeOf` inference, 100% coverage on `manifest.ts`.
- Paths: `packages/core/src/modules/`, `packages/core/biome.json`, `docs/platform/manifest.md`.
- ADR: [0014-module-manifest](../../adr/0014-module-manifest.md)

## Re-open criteria

This decision is revisited when any of these becomes true — not on a feeling,
and not because something new is shiny:

- **Date.** `reviewDate` in the frontmatter passes while the status is `Accepted`.
- **Fact.** A named, checkable fact flips, e.g. "the runner-up ships ARIA grid
  support", "the chosen library goes 12 months without a release", "the
  license changes tier under `ops/licenses/policy.yaml`".
- **Budget.** A measured number crosses a stated line, e.g. "bundle share of
  this library exceeds 60 KB gzipped in `apps/web`".
- **Advisory.** A critical advisory lands with no patched version within 14 days.

Re-opening means a new scorecard run and a new ADR that supersedes this one;
this file then becomes `Superseded by <nnnn>` with `supersededBy` set. Reverting to
`Proposed` is allowed and is logged as a reopen under References.
